# Use Case: Force-End a Game

## Overview

**Use Case ID:** UC-027
**Use Case Name:** Force-End a Game
**Primary Actor:** Operator
**Goal:** Stop a running game immediately
**Status:** Implemented
**Requirements:** FR-028

## Preconditions

- A game session is STARTING or RUNNING.

## Main Success Scenario

1. Operator presses Stop in the dashboard (or calls ForceEndGame with a reason and optionally a game id).
2. System finds the target session (the primary game when no id is given).
3. System stops the game loop, waits up to 2 s for it to finish, sets the session to ENDED and publishes `game_force_ended` with the reason and the game id; no winner is declared. The game records the outcome `force_ended` with the reason on its root span (`game.outcome`, `game.end_reason`) unless its loop had already ended on a win (#1328); JoustFFA also sends them in `game_ended` (`outcome`, `reason`) and marks survivors `player_survived`, not `victory` (UC-020 A4, BR-003).
4. System retires the session, so a new game can start.
5. The menu restores the lobby (for the primary game).

## Alternative Flows

### A1: Unknown game id

**Trigger:** No session has the given id (step 2)
**Flow:**

1. System returns `success=false` with an `Unknown game_id` error; nothing changes. A given id never falls back to the primary game.
2. Use case ends.

### A2: No game in progress

**Trigger:** No id is given and no primary game exists, or the target session is not STARTING or RUNNING (step 2)
**Flow:**

1. System returns `success=false` with `No game in progress`; nothing changes.
2. Use case ends.

### A3: Agent ends the game

**Trigger:** The agent applies `end_game` (UC-040) (step 1)
**Flow:**

1. The coordinator force-ends only the session the `end_game` value is addressed to (UC-040 A18, BR-011), with the reason `agent_intervention`, through the same path as ForceEndGame with that game id.
2. Use case continues at step 3.

## Postconditions

### Success Postconditions

- The session is ENDED and retired; the lobby is available.
- The next game starts and delivers its events normally (BR-002).

### Failure Postconditions

- The session continues.

## Business Rules

### BR-001: Shadow games by id

Shadow games are ended only by explicit game id; an empty id targets the primary game. The agent's `end_game` is always addressed to the game it was decided for, so a shadow game's decision never ends the real game (#1310, PR #1315).

Known gap (step 3): after the loop stops, the mode's end-game step still runs: Werewolf, Zombies, Swapper, Fight Club and NonStop still declare a winner (winner event, rainbow or sound) next to `game_force_ended` (issue #1343). JoustFFA no longer does (#1370).

**Code / tests:** `services/game_coordinator/servicer.py` (`ForceEndGame`, `_force_end_current_game`, `_force_end_session`, `_retire_session`), `game_session.py` (`force_end`), `interventions.py` (`_handle_end_game`); tests `services/game_coordinator/tests/test_servicer_sessions.py`, `services/game_coordinator/tests/test_servicer.py`, `services/game_coordinator/tests/test_ffa_uc020.py`, `services/game_coordinator/tests/test_intervention_scoping.py`, `tests/integration/test_parallel_lifecycle.py`, `tests/integration/test_concurrent_games.py`.

### BR-002: A new game starts normally after a force-ended game

Force-ending a game never leaves the coordinator unable to start or stream the next game. Each game runs on its own event loop, so the event bus that carries game events (the persistent primary bus above all) must work from any loop: the next game publishes its lifecycle events and reaches RUNNING, and stream subscribers receive them without delay, without a coordinator restart (#1300).

**Code / tests:** `services/game_coordinator/event_bus.py`; tests `services/game_coordinator/tests/test_event_bus_cross_loop.py`.
