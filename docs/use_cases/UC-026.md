# Use Case: Play Non-Stop Joust

## Overview

**Use Case ID:** UC-026
**Use Case Name:** Play Non-Stop Joust
**Primary Actor:** Player
**Goal:** Die least often before the time limit
**Status:** Implemented
**Requirements:** FR-026, FR-140, FR-142

## Preconditions

- A NonStop game was started with at least two players (UC-010).

## Main Success Scenario

1. System starts the game and counts deaths per player; `score` stays 0 during play.
2. A player whose movement exceeds the threshold dies (`player_death`), the death is counted, and the player respawns after `nonstop.respawn_seconds` (default 3 s) with `nonstop.spawn_protection_seconds` (default 2 s) of protection (`player_respawned`).
3. When `nonstop.time_limit_seconds` is reached, System computes each score as max(0, base − deaths × penalty) (`nonstop.scoring`, default base 100, penalty 10), picks the highest (ties: fewest deaths), publishes `game_winner` and `game_ended`.

## Alternative Flows

### A1: Unlimited time

**Trigger:** `nonstop.time_limit_seconds` is 0 (default) (step 3)
**Flow:**

1. The game never ends by itself; an operator ends it (UC-027), and no winner is declared.
2. Use case ends.

## Postconditions

### Success Postconditions

- The highest scorer is in the event stream; the session is ENDED.

### Failure Postconditions

- `game_error` ends the session.

## Business Rules

### BR-001: Scoring

Score = max(0, base − deaths × penalty), computed once at game end (`nonstop.scoring`, default base 100 and penalty 10; `services/game_coordinator/games/nonstop_joust.py` `_end_game_impl`).

Known gap (step 3): the time limit never ends the game, because NonStop's own game loop never sets the start time the limit is measured from, and the winner rainbow is skipped because the loop drops the gameplay stream before the end-game step (issue #1338).

Known gap (A1): a force-end still runs the end-game step, which publishes `game_winner` and `player_analytics` (issue #1343; moved from UC-027 BR-001 by #1602).

Known gap (lobby): selecting NonStop in the lobby plays no mode announcement and shows the default orange, because the voice and colour maps use the key `NonstopJoust` while the enum name is `NonStop` (D-M8, issue #1276; moved from UC-011 A3).

### BR-002: Root-span outcome

NonStop uses the base `run()` and records the game root-span outcome as in UC-020 BR-003: `completed` for a natural end, or `force_ended` with the force-end reason (`game.end_reason`) when force-ended. A force-end after the loop ended does not rewrite the outcome.

**Code / tests:** `services/game_coordinator/games/nonstop_joust.py` (`_game_loop`, `_check_win_condition`, `_end_game_impl`); tests `tests/integration/test_parallel_lifecycle.py` (NonStop), `services/game_coordinator/tests/test_mode_run_outcome.py` (UC-026 BR-002).
