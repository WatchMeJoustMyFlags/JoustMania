# Use Case: Configure Settings in Admin Mode

## Overview

**Use Case ID:** UC-012
**Use Case Name:** Configure Settings in Admin Mode
**Primary Actor:** Host
**Goal:** Calibrate the game from a controller and persist the settings
**Status:** Implemented
**Requirements:** FR-008, FR-016, FR-017, FR-018, NFR-006, C-008
**Planned:** FR-014 (#1277, Open)

## Preconditions

- The menu is RUNNING; no other controller is in admin mode.

## Main Success Scenario

1. Host presses Cross, Circle, Square and Triangle together.
2. System flashes the controller white, switches it to ADMIN (persistent white) and starts a 60 s timer.
3. Host presses Move to cycle the option: sensitivity (blue), num_teams (turquoise), force_all_start (orange), agent_control (purple).
4. Host presses Select to step the selected option forward or Start to step it backward.
5. System rewrites the option's `defaultVariant` in `game.json` (in place) and gives feedback: a colour pulse and a voice line (sensitivity: 5 levels blue to red; num_teams: number voice; force_all_start: on/off voice).
6. flagd reloads the file; the next game uses the new value.
7. Host presses PS to leave admin mode.
8. System returns the controller to CONNECTED (dim).

## Alternative Flows

### A1: Circle cycles sensitivity directly

**Trigger:** Host presses Circle (step 3)
**Flow:**

1. System cycles `sensitivity` forward through ultra_slow … ultra_fast with colour and voice feedback.
2. Use case continues at step 6.

### A2: Show battery levels

**Trigger:** Host presses Triangle (step 3)
**Flow:**

1. System flashes every controller in a colour for its battery level (≥ 100 green, ≥ 80 turquoise, ≥ 60 blue, ≥ 40 yellow, else red) for 1 s.
2. Use case continues at step 3.

### A3: Toggle instructions

**Trigger:** Host presses Square (step 3)
**Flow:**

1. System toggles `game_instructions` in `user.json` with a green / red pulse and voice.
2. No service reads this flag today, so gameplay audio is unchanged (D-F1).
3. Use case continues at step 3.

### A4: Timeout

**Trigger:** 60 s have passed since the host entered admin mode (step 3)
**Flow:**

1. System exits admin mode. The timer is not extended by activity.
2. Use case continues at step 8.

### A5: Write fails

**Trigger:** The flag file is not writable (step 5)
**Flow:**

1. System logs an error (CRITICAL when the file is not writable); the setting is not persisted.
2. Use case continues at step 3.

### A6: Agent control and force start

**Trigger:** Host selects `agent_control` (see UC-013) or holds the trigger (see UC-014) (step 3)
**Flow:**

1. System hands over to UC-013 (agent control) or UC-014 (force start).
2. Use case ends.

## Postconditions

### Success Postconditions

- The new baseline is in `game.json` / `user.json` and applies from the next game on.

### Failure Postconditions

- The flag file is unchanged.

## Business Rules

### BR-001: Settings are frozen per game

Admin changes apply to the **next** game; a running game keeps the values it started with (`force_all_start` is read at force start).

### BR-002: Not every flag is controller-cycled

`random_assignment`, `nonstop.time_limit_seconds`, `invincibility_seconds`, `fight_club.min_rounds` and `werewolf.reveal_time_seconds` are set by file or flagd only (#815).

### BR-003: Werewolf sensitivity

`sensitivity` targeting forces level 3 for Werewolf, so the admin baseline does not apply there.

Known gap (precondition): nothing enforces a single admin; a second controller that completes the combo takes over the admin session while the first stays in ADMIN (issue #1341).
