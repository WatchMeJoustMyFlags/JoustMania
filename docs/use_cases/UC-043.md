# Use Case: Run a Shadow Experiment and Promote the Winner

## Overview

**Use Case ID:** UC-043
**Use Case Name:** Run a Shadow Experiment and Promote the Winner
**Primary Actor:** Agent
**Goal:** Find out in shadow games whether a flag value improves an objective, and promote it only if it does
**Status:** Implemented
**Requirements:** FR-029, FR-055, FR-060, FR-061, FR-062, FR-063, FR-064, FR-065, FR-066, NFR-018, C-003, C-005, C-007
**Planned:** FR-067 (#964, Open), FR-068 (#1011, Open), FR-105 (#1258, Open), FR-106 (#1258, Open)

## Preconditions

- `enabled` and `experiments_enabled` are on.
- An experiment is declared (env seed, proposer, thesis or dynamic declarer).

## Main Success Scenario

1. The agent writes an experiment variant `agent_experiment__<id>` into `game.json`, targeted at `game_kind != real` and the experiment's id and arm; the gate rejects any write that would change what a real game resolves.
2. Every `experiment_tick_seconds` (default 30) the agent spawns pairs of shadow games (experimental, control) through the coordinator and mock-controller APIs, sharing a random seed, with agent origin and reserved mock controllers.
3. The coordinator runs them as shadow games with their own game ids (UC-003 A2) and the agent observes them (UC-041).
4. On each game end the agent scores fitness for the objective and adds the sample to the arm.
5. When both arms reach `verdict_min_n` (default 8) games and `verdict_min_pairs` (default 5) pairs, the agent computes Cohen's d; a promote verdict needs the effect threshold (0.5) and the raw-effect floor (0.02), and the recent-real baseline anchor may downgrade it to inconclusive.
6. On a promote verdict the agent routes the experiment to the promoter in `code_improvement.mode` (default `issue`).
7. The promoter acts per mode: open an issue, open a PR (or commit locally) for human review, or (autonomous) apply the real default, watch real games and revert on degradation.
8. The agent tears the experiment down and journals intent, events and summary on the `agent-experiments` volume.

## Alternative Flows

### A1: Kill switch or experiments off

**Trigger:** `enabled` or `experiments_enabled` turns off (any step)
**Flow:**

1. The agent aborts every running experiment on the next tick.

### A2: Real game starts

**Trigger:** A menu game starts while shadow games run (step 3)
**Flow:**

1. The coordinator preempts live shadow games; with `shadow_policy=block` no new shadow game starts until the real game ends.

### A3: Inconclusive or discard

**Trigger:** No significant effect (step 5)
**Flow:**

1. The experiment keeps running until `experiment_max_games` (default 50), then concludes as discard / inconclusive without promotion.

### A4: Promotion inert

**Trigger:** The promotion env gates are not set (stock stack) (step 7)
**Flow:**

1. The promoter records a discarded no-op promotion with a reason (D-A6).

## Postconditions

### Success Postconditions

- A verdict is journaled; a promote verdict produced an issue, a PR or (autonomous) a watched real-default change.

### Failure Postconditions

- Real games never saw the experimental variant.

## Business Rules

### BR-001: Shadow-only

`experiment_id`, `arm` and `rng_seed` apply only to shadow sessions; a real start ignores them.

### BR-002: No chaos experiments

The `chaos` objective cannot be experimented on.

### BR-003: Tier 3 needs a human

Issue and PR modes never change a running system; a human merges.
