# Use Case: Present the Talk Demo

## Overview

**Use Case ID:** UC-070
**Use Case Name:** Present the Talk Demo ("Two Standards Walk Into an Agent")
**Primary Actor:** Presenter
**Goal:** Show live that OpenTelemetry is the agent's nervous system and OpenFeature its will
**Status:** Implemented
**Requirements:** FR-090, FR-091, FR-092, FR-093, FR-094, FR-095, FR-045, FR-042, FR-056, NFR-011, C-004, C-018

Backend roles follow C-018: **Jev** is the main in-game backend, **Claude** is the manual in-game backup and
writes the post-game summary (retro), **rules** is the automatic floor. The experiments / shadow-game act is not
part of this talk; it is described in `docs/agent-dry-run-runbook.md` (UC-043). On the talk stage the
experiment loop runs only in the screen-only fallback when Bluetooth fails at the venue (A9); the stage baseline keeps
`experiments_enabled` off otherwise.

## Preconditions

- Demo stack up: the Pi stage stack with real controllers, or `make dry-run` (mock controllers) as the rehearsal /
  fallback stack, with `experiments_enabled` off.
- `.env.local` holds `JEV_API_KEY`, `ANTHROPIC_API_KEY`, `AGENT_INFERENCE_BACKEND=claude` and the rehearsed
  `IMAGE_TAG` (the tracked `.env` pins an older release). On the Pi, the manual bring-up and the systemd autostart
  both go through `scripts/setup/joustmania-compose.sh`, which passes `.env` and then `.env.local`, so a reboot comes
  back on the same tag with the keys (#1488).
- Flags at the stage baseline (runbook section 6): `decision.backend=rules` at session start,
  `decision.jev.act_confidence_threshold=gate` (0.6), `decision.act_confidence_threshold=default` (0.8),
  `decision.claude.timeout_ms=default` (5000 ms), `llm.max_requests_per_minute=stage` (30; or
  `AGENT_LLM_MAX_REQUESTS_PER_MINUTE` ≥ 30, which replaces the flag), `enabled` and `interventions_enabled` on,
  `interventions_allowed=standard` (BR-003), applied by `scripts/talk-stage.sh reset`.
- Pre-flight check clean (`scripts/talk-preflight.sh`), including the perceptible-intervention and audio-cue checks (BR-004)
  and at least `TALK_MIN_CONTROLLERS` (default 2) real PS Move controllers connected (BR-006).

## Main Success Scenario

1. **Observe:** With a game running on `rules`, the presenter shows the dashboard Agent tab and an `agent.decide`
   span in Jaeger (rationale, confidence).
2. **Switch to the main in-game backend:** Presenter runs `scripts/agent-backend.sh jev` (UC-044). Calm play yields `noop`
   (Jev's gate p_yes about 0.16); players near the death threshold or a collapsing game yield `act` (p_yes about
   0.72 / 0.68 ≥ 0.6), with the gate value on the stage-1 chat span. Rounds take about 0.22-0.34 s (noop) and
   0.47-0.57 s (act). An act is perceptible: a shield turns the player's LED and dashboard tile white with a
   countdown badge and plays the shield sound (UC-040 A16), a tempo change is heard in the music, an audio cue
   plays the lobby ping.
3. **Permissions, threshold:** Presenter runs `scripts/agent-backend.sh jev-threshold strict` (0.95); the answers
   that acted are now `held`, calm answers stay `noop`. Presenter restores `jev-threshold gate`.
4. **Backup:** Presenter runs `scripts/agent-backend.sh claude` (manual flip, no automatic chain); decisions show
   backend `claude`, the global threshold and about 3 s latency.
5. **Kill switch:** Presenter runs `scripts/agent-killswitch.sh off` right after a Claude call starts; no decisions
   on any backend, an in-flight Claude answer is `discarded` with `kill_switch` (likely, about 3 in 4 tries; measured
   in rehearsal), and post-game model calls stop too; the infrastructure loop
   (governed by `rollout_enabled`) is not stopped (UC-045). Presenter switches the agent back on.
6. **Rollback:** Presenter runs `scripts/agent-backend.sh jev`; no container restarts.
7. **Degrade:** Presenter selects the shipped `blackhole` variant of `decision.jev.base_url` (TEST-NET-1 over https)
   or cuts the uplink (restored before the game ends); decisions fall back to rules in the same cycle
   (`fallback_reason` `timeout` when the 2.5 s Jev timeout expires, or `error` when the network rejects the call within it) and the game keeps playing (UC-040 A2).
8. **Summary:** The game ends; the `agent.llm.retro` span shows Claude's session assessment and suggested
   improvements (`inference.used=claude`, `retro.suggestion` events), linked to the game trace.
9. Presenter runs `scripts/talk-stage.sh reset`, which restores the stage baseline, and then the pre-flight check.

## Alternative Flows

### A1: Infrastructure beat (optional)

**Trigger:** Stage stack with a real controller on the python adapter, after the degrade beat (step 7). Cut from the talk (hardware only, see the talk runbook); UC-050 / UC-051 are parked since 2026-10-19. This flow is **parked** with them (maintainer decision, 2026-10-20, #1655): it stays as written and its code and tests stay, but it is not audited and does not hold back this use case until UC-050 / UC-051 are un-parked (#1322); FR-071 (progressive rollout) and FR-072 (automatic rollback) left this Requirements line for the same reason and stay with UC-050 and UC-051
**Flow:**

1. Presenter turns `rollout_enabled` (`agent.json`) and `remediation_allowed` (`rollout.json`) on first, then sets `target_backend=unstable` and, last, `strategy=progressive` (UC-050); the agent expands, detects the violation and rolls back (UC-051), then repeats about every 30 s.
2. Presenter resets the rollout flags (`strategy`, `target_backend`, `current_controller_count`, `remediation_allowed`, `rollout_enabled`) through the flag service (runbook section 4); no agent restart: the agent drops its last written stage once the rollout is inactive or the served stage is no longer its write (UC-050 BR-001, #1384). A post-rollback cooldown still running (up to `AGENT_ROLLOUT_COOLDOWN_SECONDS`, 30 s) holds the first expansion of the next run. A dry run keeps no rollout state either (UC-050 BR-003).
3. Use case continues at step 8.

### A2: Jev unreachable or slow at the venue

**Trigger:** Decisions show `jev -> rules` with `timeout`, `error` or `backend_unavailable` (step 2 or 6)
**Flow:**

1. Rules decided every affected cycle, so the game did not stall.
2. Presenter flips the backup backend, `scripts/agent-backend.sh claude`; on Claude the global threshold applies
   (`scripts/agent-backend.sh threshold strict` shows `held`).
3. Use case continues at step 3 (from step 2) or step 7 (from step 6), on Claude.

### A3: Remote decisions time out on Claude

**Trigger:** A Claude call exceeds `decision.claude.timeout_ms` (default 5000 ms; warm Haiku about 2.7-3.0 s,
Sonnet about 2.85 s) (step 4)
**Flow:**

1. Decisions show `fallback` with `timeout`.
2. Presenter selects `patient` (8000 ms) or switches back to Jev.
3. Use case continues at step 5.

### A4: Budget exhausted

**Trigger:** The shared per-minute budget (decisions and the post-game summary) runs out on the first remote backend (step 2)
**Flow:**

1. Decisions fall back with `llm_budget_exhausted`; at game end the retro is gated before any span is created
   (only the log `agent.llm.retro_gated` with `fallback_reason=llm_budget_exhausted`).
2. Presenter selects the `stage` variant of `llm.max_requests_per_minute` (30 per minute), unless
   `AGENT_LLM_MAX_REQUESTS_PER_MINUTE` is set (it replaces the flag; changing it needs an agent restart). The same
   fix applies when it happens on Claude (step 4); at game end it shows as A5.
3. Use case continues at step 2.

### A5: No summary at game end

**Trigger:** No `agent.llm.retro` span with `llm.retro.parse_ok=true` for the finished game (step 8)
**Flow:**

1. No retro span at all: the budget was full at game end (A4).
2. A span with `inference.used=none`: `inference.fallback_reason` names the cause, `no_backend_available`
   (`AGENT_INFERENCE_BACKEND` not `claude`) or `agent_disabled` (the kill switch was off at game end).
3. A span with `inference.used=claude` and `llm.retro.parse_ok=false`: the model call failed (`llm.infer.error`,
   span status error, log `agent.llm.retro_failed`).
4. Presenter shows the summary of an earlier game.
5. Use case continues at step 9.

### A6: Second vendor (optional)

**Trigger:** Presenter has added model and base URL variants to `decision.openai.*`, after the rollback (step 6)
**Flow:**

1. Presenter runs `scripts/agent-backend.sh openai <variant>`; without the variants or `DECISION_OPENAI_API_KEY` it
   falls back with `backend_unavailable`.
2. Presenter runs `scripts/agent-backend.sh jev`.
3. Use case continues at step 7.

### A7: Permissions beat (optional)

**Trigger:** Presenter shows the allow-list after the threshold beat (step 3)
**Flow:**

1. Presenter runs `scripts/talk-stage.sh permissions none 12`; on a remote backend no new decide rows appear, because the agent skips a call whose only option would be `noop` (UC-040 A14); on rules every non-noop decision is blocked `not_allowed`.
2. After 12 s, or when the presenter presses Enter, the helper restores the baseline `interventions_allowed` (`standard`). It also restores it when the beat is interrupted (Ctrl-C, closed terminal, `TERM`).
3. Use case continues at step 4.

### A8: A beat left the flags off the baseline

**Trigger:** The helper of a beat was killed before it could restore (e.g. `SIGKILL`), or a flag was flipped by hand and not flipped back; the pre-flight check FAILs (step 9)
**Flow:**

1. Presenter runs `scripts/talk-stage.sh reset`: every stage overlay is cleared and every baseline flag of the agent set is set to its stage variant, whatever the beat left behind; game-scoped interventions need no reset (they die with their game, [UC-053](UC-053.md) BR-003).
2. Presenter runs `scripts/talk-preflight.sh`; it passes.
3. Use case ends.

### A9: Bluetooth down at the venue (screen-only fallback)

**Trigger:** The pre-flight check FAILs the real-controller count (BR-006), or the real controllers drop during a beat (step 1 to step 7)
**Flow:**

1. Presenter runs `scripts/talk-stage.sh fallback on`: it sets `llm.eligible_game_kinds=real_and_shadow` (remote
   backends may decide on shadow games), `experiments_enabled=on`, `experiment_dynamic_enabled=on` (the agent
   declares experiments itself) and `experiment_tick_seconds` to its 10 s variant, the stage `fallback` section of
   `scripts/talk-baseline.json`, in place.
2. The experiment loop spawns shadow games on pattern-driven mock controllers (UC-046) over
   `experiment.mock_archetypes`; the stage selection includes `calm_long`, which kills nobody and runs until
   `experiment.max_game_seconds` (300 s), so a game is in progress (BR-007).
3. With no real game live, the dashboard follows the newest live shadow game (BR-005): the current-backend strip
   shows its backend with the `shadow` badge, and the Controllers tab adds that game's tiles (LED colour, shield
   badge, alive or dead) under a "following shadow game" banner. Real and lobby controllers stay on the grid; the
   lobby and the menu never show the shadow controllers.
4. The pre-flight check WARNs (not FAILs) on the real-controller count and accepts the fallback variants (BR-006).
5. Beats 2 to 7 run on the shadow game's decisions; remote calls on shadow games count against
   `llm.max_requests_per_minute`, which bounds the cost. The kill-switch beat (step 5) aborts the experiments and
   force-ends their shadow games, so the screen has no game until the agent is switched back on and the next
   experiment tick (10 s) has declared an experiment and spawned its games (BR-007); the presenter narrates that gap
   or skips the beat.
6. Presenter runs `scripts/talk-stage.sh fallback off` (or `reset`) when real controllers are back, or after the talk.
7. Use case continues at step 8.

## Postconditions

### Success Postconditions

- Every beat produced a visible effect in the game, the dashboard and Jaeger; flags are back at baseline.

### Failure Postconditions

- The game kept playing on rules.

## Business Rules

### BR-001: Demo flags through the flag service

The helper scripts change flags through the flag service of the stack that is up (`FLAG_SERVICE_URL`, default the envoy route `http://localhost/flags`); they edit no file, so the same commands work on the rehearsal (`services/flagd/ci/` baseline) and the Pi stage stack (`services/flagd/`).

### BR-002: Measured latencies

The Jev and Claude latencies above are development-machine measurements (decide contract §8); stage latencies
are to be measured in rehearsal (runbook section 9, #743).

### BR-003: Stage baseline lives in the stage helper

The act beats run with `interventions_allowed=standard`, so `grant_shield` and `adjust_music_tempo` can fire, and with
`policy.max_interventions_per_minute=aggressive` (4 per minute), so a beat's act is not refused by the per-game
budget the previous beat spent (#1326; the shipped default stays 2). This
baseline lives in `scripts/talk-baseline.json` (read by `scripts/talk-stage.sh` and `scripts/talk-preflight.sh`), not
in the shipped flag files, whose default stays `ambient` (#1301).

### BR-004: The pre-flight check proves the audience can perceive an act

`scripts/talk-preflight.sh` FAILs when `interventions_allowed` is not the stage baseline (it names `none` and `probe`
explicitly), when the resolved allow-list contains no perceptible intervention (glossary), and when the writer
default audio cue (`defaultAudioCue` in `services/agent/actions/writer.go`) does not resolve to a file in the running
audio container (`python -m services.audio.sound_catalog`).

### BR-005: The dashboard follows a shadow game only when no real game is live

The game the dashboard follows is the real (primary) game while it is `STARTING`, `RUNNING` or `ENDING`. Without one
it is the newest live shadow game (state `STARTING` or `RUNNING` in `ListGames`, newest `start_time_ms`), and it stays
on that game while it is live, also across a transient poll error, so concurrent shadow games do not make the view
flicker. The current-backend strip describes the followed shadow game when it has decide rows; without a live real
game and without such rows it describes the game of the newest row of any kind. The controller grid hides the
players of live shadow games, except the followed game's players, which it adds (from `GetGameState(game_id)`; alive
or dead from `PlayerInfo.alive`; shield badges from that game's own `StreamGameEvents(game_id)`); a controller that
is in no live shadow game (a real or lobby controller) is never hidden, and the player count covers the tiles shown.
Shadow (pattern) controllers stay reserved: hidden from the lobby and the menu (UC-046); the filter is dashboard-only.

### BR-006: The pre-flight check counts real controllers

`scripts/talk-preflight.sh` counts the connected controllers that controller-manager reports
(`GetConnectedControllers` through envoy; reserved controllers are not listed) whose serial is not a mock serial
(`MOCK...`, `mock_...`). Fewer than `TALK_MIN_CONTROLLERS` (default 2) is a FAIL that names the fallback; with the
fallback on (`llm.eligible_game_kinds=real_and_shadow`) it is a WARN. Controller-manager unreachable is a FAIL (a WARN
with the fallback on) that does not suggest the fallback, which needs controller-manager too. With the fallback on,
the check expects the `fallback` variants of `scripts/talk-baseline.json` (`llm.eligible_game_kinds`,
`experiments_enabled`, `experiment_dynamic_enabled`, `experiment_tick_seconds`) instead of the stage baseline.

### BR-007: A game is always in progress in the fallback

The fallback relies on the experiment loop: `experiments_enabled=on` and an experiment declared. The heuristic
dynamic declarer (`experiment_dynamic_enabled=on`) keeps declaring experiments, also after the kill-switch beat or
a `fallback off` aborted them (the `AGENT_EXPERIMENT_SEED_*` env seed is declared only once per agent start). The
archetype selection `experiment.mock_archetypes` must include `calm_long`; `talk-stage.sh reset` restores the shipped
`all` selection, and `fallback on` and the pre-flight check WARN in fallback mode when `calm_long` is missing.

### BR-008: The dynamic declarer experiments on game tuning only

Without an explicit `AGENT_EXPERIMENT_DYNAMIC_CANDIDATES` list, the dynamic declarer rotates over every tunable
`game.json` flag except its default denylist (`defaultDynamicDenylist`, overridable with
`AGENT_EXPERIMENT_DYNAMIC_DENYLIST`): the experiment plumbing `shadow_policy`, the session capacity
`max_concurrent_games` and `max_shadow_games`, the tempo source `tempo_schedule_mode`, the lobby start controls
`force_all_start` and `force_all_start_seconds`, and the ceremony timing `countdown_phase_duration_ms` and
`winner_rainbow_duration_ms`. These do not tune play, so an experiment on them measures nothing (#1316).
