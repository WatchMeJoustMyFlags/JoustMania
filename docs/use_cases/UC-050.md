# Use Case: Roll Out a Controller Backend Progressively

## Overview

**Use Case ID:** UC-050
**Use Case Name:** Roll Out a Controller Backend Progressively
**Primary Actor:** Operator
**Goal:** Move controllers to a new HID backend a few at a time, advanced by the agent while health is good
**Status:** Implemented
**Requirements:** FR-071, FR-074, NFR-016, NFR-017

## Preconditions

- At least one real controller on a python HID adapter (mock-only controllers are not routed; `unstable` is only registered with a python adapter).
- `rollout_enabled` is on (otherwise the agent only dry-runs).

## Main Success Scenario

1. Operator sets `target_backend` (e.g. `unstable` for the demo, or `rust`) and `strategy=progressive` in `rollout.json`.
2. System's controller manager publishes rollout target, strategy and count on the ~1 Hz `controller.bluetooth_health` span together with Bluetooth health samples.
3. The agent sees an active rollout and evaluates infrastructure fitness: event gap ≤ 50 ms, dropped events ≤ 2 %, movement update rate ≥ 10 Hz.
4. Fitness passes and the dwell time (`AGENT_ROLLOUT_DWELL_SECONDS`, default 15 s) has elapsed.
5. The agent advances `current_controller_count` to the next stage (0 → 1 → 3 → 6 → all) in `rollout.json`.
6. The controller manager routes the first N controllers (sorted by serial) to the target backend on its next cycle.
7. Steps 3 to 6 repeat until all controllers are on the target.
8. Every cycle is recorded as an `agent.infrastructure.decision` span.

## Alternative Flows

### A1: Immediate strategy

**Trigger:** `strategy=immediate` (step 1)
**Flow:**

1. The controller manager routes every controller to the target at once; the agent only observes.

### A2: Fitness fails

**Trigger:** A threshold is violated (step 3)
**Flow:**

1. Use case continues in UC-051.

### A3: Dry run

**Trigger:** `rollout_enabled` is off (step 5)
**Flow:**

1. The agent records the expansion it would make and changes nothing.

### A4: Manual override

**Trigger:** A controller has per-serial `bluetooth_backend` targeting (UC-052)
**Flow:**

1. The manual routing wins over the rollout for that controller.

## Postconditions

### Success Postconditions

- All controllers run on the target backend; the trace shows each stage and its fitness.

### Failure Postconditions

- The rollout stays at its last stage (or rolls back, UC-051).

## Business Rules

### BR-001: Agent writes only the count

The agent writes `current_controller_count`; `target_backend` and `strategy` are human-owned.

### BR-002: Fresh data required

The agent decides only when at least one controller has fresh health data.
