# Use Case: Switch the Decision Backend Live

## Overview

**Use Case ID:** UC-044
**Use Case Name:** Switch the Decision Backend Live
**Primary Actor:** Operator
**Goal:** Change who decides in-game (rules, Claude, an OpenAI-compatible model, Jev) without a restart
**Status:** Implemented
**Requirements:** FR-045, FR-054, NFR-014, C-005, C-006, C-016

## Preconditions

- The agent runs; the API key for the target backend was present in the environment at agent startup.

## Main Success Scenario

1. Operator runs `scripts/agent-backend.sh jev` to select the main in-game backend, or `scripts/agent-backend.sh claude sonnet` to fall back to Claude manually (or edits `decision.backend` / `decision.<backend>.model`).
2. System rewrites the default variants in the agent flag file (by default `services/flagd/ci/agent.json`).
3. flagd reloads the file.
4. On its next decision cycle the agent reads the new backend and model (flags are never cached) and uses them for the next remote call (UC-040).
5. `agent.decide` spans show `decide.backend.requested` and `decide.backend` with the new value.

## Alternative Flows

### A1: Missing key or model

**Trigger:** No API key, no model (e.g. `decision.openai.model` is empty by default) or no base URL (step 4)
**Flow:**

1. Decisions fall back to rules with `backend_unavailable` (UC-040 A3).
2. Use case ends.

### A2: Switch while a call is in flight

**Trigger:** The backend changes during a remote call (step 4)
**Flow:**

1. The late answer is discarded with `backend_changed`.
2. Use case continues at step 5.

### A3: Tune without switching

**Trigger:** Operator runs `agent-backend.sh threshold strict`, `jev-threshold inherit`, `capture on`, or `effort low` instead of switching (step 1)
**Flow:**

1. System changes `decision.act_confidence_threshold`, `decision.jev.act_confidence_threshold`, `decision.capture_content` or `decision.openai.reasoning_effort`; applies on the next decision. `agent-backend.sh status` (or no argument) shows the current values.
2. Use case continues at step 3.

### A4: Wrong flag file

**Trigger:** The stack serves `services/flagd/` but the script edits `services/flagd/ci/` (step 2)
**Flow:**

1. Nothing changes; set `AGENT_FLAG_FILE` to the served file.
2. Use case ends.

## Postconditions

### Success Postconditions

- The next remote decision uses the new backend.

### Failure Postconditions

- Decisions continue on the previous backend or on rules.

## Business Rules

### BR-001: Keys never in flags

API keys come from the environment only and are read once at startup; a new key needs a restart.

### BR-002: Backend roles

See [C-018](../requirements.md#constraints). Jev needs only `JEV_API_KEY`; its wire format is in [decide-contract.md](../specs/decide-contract.md).
