# Use Case: Switch the Decision Backend Live

## Overview

**Use Case ID:** UC-044
**Use Case Name:** Switch the Decision Backend Live
**Primary Actor:** Operator
**Goal:** Change who decides in-game (rules, Claude, an OpenAI-compatible model, Jev) without a restart
**Trigger:** Operator wants another decision backend or model for the next decisions (for example the talk's switch to Jev, or Claude as the backup)
**Status:** Tested
**Requirements:** FR-045, FR-049, NFR-050, NFR-052, C-004, C-005, C-006, C-016, C-018, C-032, C-033
**Planned:** FR-150 (#1788, Implemented), FR-151 (#1788, Obsolete since #1907: the env fallbacks are removed)

## Preconditions

- The agent runs.

## Main Success Scenario

1. Operator runs `scripts/agent-backend.sh jev` to select the main in-game backend, or `scripts/agent-backend.sh claude sonnet` to select the backup backend Claude by hand (or sets `decision.backend` / `decision.<backend>.model` with `scripts/flags.sh`).
2. System sets the variants as stack-wide values on the flag service. `scripts/agent-backend.sh` writes the backend and model persisted (they survive a flag-service restart, Post-S-2); other stage writes (`flags.sh` without persist, `talk-stage.sh` beats) stay in memory ([UC-053](UC-053.md) A1). The flag files are unchanged.
3. The new values reach flagd within the write-propagation bound (NFR-050).
4. On its next decision cycle the agent reads the new backend and model and uses them for the next remote call (UC-040).
5. `agent.decide` spans show `decide.backend.requested` and `decide.backend` with the new backend, and `gen_ai.request.model` with the new model.

## Alternative Flows

### A1: Missing key or model

**Trigger:** The selected backend's API key was not in the environment at agent startup (`ANTHROPIC_API_KEY` for `claude`, `DECISION_OPENAI_API_KEY` for `openai`, `JEV_API_KEY` for `jev`), `claude` or `openai` has no model (e.g. `decision.openai.model` is empty by default) or, for `openai`, no base URL (only when an operator cleared it: the shipped `agent.json` default of `decision.openai.base_url` is `https://api.openai.com/v1`) (step 4; Jev and `claude` default an empty base URL to their API roots), or the selected `openai` / `jev` / `claude` base URL is not key-safe (BR-003)
**Flow:**

1. Decisions fall back to rules with `backend_unavailable` (UC-040 A3).
2. Use case ends.

### A2: Switch while a call is in flight

**Trigger:** The backend changes during a remote call (step 4)
**Flow:**

1. The late answer is discarded with `backend_changed`. A change of the model alone does not discard it; the next call uses the new model.
2. Use case continues at step 5.

### A3: Tune without switching

**Trigger:** Operator runs `agent-backend.sh threshold strict`, `jev-threshold inherit`, `capture on`, or `effort low` instead of switching (step 1)
**Flow:**

1. System sets `decision.act_confidence_threshold`, `decision.jev.act_confidence_threshold`, `decision.capture_content` or `decision.openai.reasoning_effort` on the flag service as in step 2; the backend stays as it is. A refused or failed write ends as in A4.
2. The new value reaches flagd within the write-propagation bound (NFR-050).
3. From the next decision on, the agent uses it: a threshold shows as `decide.act_confidence_threshold` and `decide.act_confidence_threshold.source` on `agent.decide` (an answer still in flight is judged by the new threshold when it lands); `capture on` adds the prompt and answer content to the decide chat spans; the effort shows as `gen_ai.request.reasoning.level` on the `openai` chat span.
4. Use case ends.

### A4: Flag service refuses or is unreachable

**Trigger:** The flag service refuses the write (the variant is not declared, `422 out_of_bounds`, [UC-053](UC-053.md) A5; flagd is not connected, `503 no_sync_stream`, UC-053 A7), the flag is not declared in the agent set, or the flag service does not answer within the script's 5 s deadline (NFR-052) (step 2)
**Flow:**

1. The script exits non-zero and the backend that was active stays active. For a variant the flag does not declare, the flag service refuses it (`out_of_bounds`) and the script prints `variant '<v>' not defined for flag '<key>'; valid: <variants>`; for a flag the set does not declare it prints `flag '<key>' not defined in the agent flag set`; when the service cannot be reached it prints `flag service unreachable`. For a backend plus model switch both variants are validated before any write, and the model is written before the backend: a write that fails midway leaves the previous backend active, and the new model value may already be set. It takes effect only when that backend is selected, or at once if that backend was already the active one.
2. Use case ends.

### A5: Show the current settings

**Trigger:** Operator runs `agent-backend.sh status` (or no argument) instead of changing a value (step 1)
**Flow:**

1. The script prints the backend, its model (`n/a` on rules), both act thresholds, content capture (and the reasoning effort on `openai`) as the flag service serves them, and the flag service address; it writes nothing.
2. Use case ends.

## Postconditions

### Success Postconditions

- The next remote decision uses the new backend and model.
- The backend and model values hold until the operator changes or clears them. `agent-backend.sh` writes `decision.backend` and the per-backend model flags as persisted values (`"persist": true`, [flags.md §13.2](../specs/flags.md#132-agent)), so they survive a flag-service restart or a Pi reboot ([UC-053](UC-053.md) A9, BR-004; C-018, #1682): flagd serves the chosen backend again and the agent keeps deciding with it (the agent sees the change on its next read: [flags.md §1.3](../specs/flags.md#13-reload-semantics)). A stage overlay over a persisted value (`talk-stage.sh`) is temporary: a restart brings the persisted value back. `talk-stage.sh reset` and `agent-backend.sh rules` both leave `rules` as the state that survives a restart.

### Failure Postconditions

- Decisions continue on the previous backend or on rules.

## Business Rules

### BR-001: Keys from the environment, read once

API keys come from the environment only, never from a flag, and are read once at startup; a new key needs a restart (a key set or removed later changes nothing, and no key ever appears in a span attribute, C-016).

### BR-002: Backend roles

See [C-018](../requirements.md#constraints). Jev needs only `JEV_API_KEY`; its wire format is in [decide-contract.md](../specs/decide-contract.md).

### BR-003: Keys travel only over TLS or loopback

The base URL a key is sent to is `https`, or plain `http` to a loopback host (`localhost`, 127.0.0.0/8, ::1), with no credentials, query or fragment. Anything else makes the backend unavailable before any request is built (A1, C-016), so rules decide with `backend_unavailable` and the key is sent nowhere. This covers `decision.openai.base_url`, `decision.jev.base_url` and `decision.claude.base_url` (#1900; claude's has no `/v1`, the SDK appends `/v1/messages`; it is independent of the text backend's `AGENT_INFERENCE_BASE_URL` env ceiling). An empty jev base URL still means the jev default and an empty claude base URL the Anthropic default. The decide HTTP client follows no redirect, so a redirect cannot carry the key to another host or downgrade it to plain `http`.
