# Use Case: Pair a Controller over USB

## Overview

**Use Case ID:** UC-001
**Use Case Name:** Pair a Controller over USB
**Primary Actor:** Player
**Goal:** Make a new PS Move controller known to the Pi's Bluetooth adapter so it can connect wirelessly
**Status:** Implemented
**Requirements:** FR-001, NFR-007, C-011, C-012

## Preconditions

- The stack is running with the pairing daemon (host network, privileged) and at least one Bluetooth adapter.
- The controller is a supported model (ZCM1, ZCM2 or ZCM2E).

## Main Success Scenario

1. Player plugs the controller into a USB port of the Pi.
2. System detects the controller on its next USB poll (every `pairing.poll_interval`, default 10 s).
3. System picks the least-loaded Bluetooth adapter.
4. System writes the adapter's address into the controller (the backend is chosen by the `bluetooth_backend` flag: `rust` uses the rust-hid PairingService, anything else the in-process hidapi backend).
5. System restarts the Bluetooth service and marks the controller as trusted.
6. System logs that the player can unplug the controller and press the PS button.
7. Player unplugs the controller.

## Alternative Flows

### A1: Controller already paired this session

**Trigger:** The serial was verified earlier in this daemon session (step 2)
**Flow:**

1. System skips pairing.
2. Use case ends.

### A2: Trust step fails

**Trigger:** `bluetoothctl trust` fails after retries (step 5)
**Flow:**

1. System logs the failure as non-fatal and keeps the pairing.
2. Use case continues at step 6.

### A3: Unknown backend value

**Trigger:** `bluetooth_backend` resolves to a value the daemon does not know, e.g. `unstable` (step 4)
**Flow:**

1. System logs a warning and uses the hidapi backend.
2. Use case continues at step 5.

## Postconditions

### Success Postconditions

- The controller stores the Pi adapter's address and is trusted by BlueZ.
- `psmove_pairing_success_total` is incremented.

### Failure Postconditions

- The controller is not paired; `psmove_pairing_failed_total` is incremented and the next poll retries.

## Business Rules

### BR-001: Adapter load balancing

New controllers go to the adapter with the fewest connected devices; an adapter holds at most 7 controllers.

### BR-002: No LED feedback

The pairing daemon gives no LED feedback during pairing (see D-C4 in [specs-inventory](../specs-inventory.md#45-controllers-pairing-leds-d-c)).
