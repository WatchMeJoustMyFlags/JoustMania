# Use Case: Select the Game Mode

## Overview

**Use Case ID:** UC-011
**Use Case Name:** Select the Game Mode
**Primary Actor:** Host
**Goal:** Choose which game mode the next game uses
**Status:** Implemented
**Requirements:** FR-011, FR-036, FR-037

## Preconditions

- The menu is RUNNING.
- The host is in admin mode (UC-012), or uses the dashboard / `ProcessInput`.

## Main Success Scenario

1. Host presses Cross in admin mode.
2. System advances to the next playable mode (the ten implemented modes, wrapping around).
3. System pulses the mode's lobby colour on the host's controller and announces the mode name in the selected voice.
4. System persists the choice as the `current_game` default variant in `user.json`.
5. System publishes `selection_changed` and `game_selection_changed` menu events.
6. System recolours lobby LEDs to the new mode's colour.

## Alternative Flows

### A1: Select via the web command

**Trigger:** A client calls `ProcessInput` with `web_command` `select_game` and a game name
**Flow:**

1. System selects that mode, announces it and persists it.
2. Use case continues at step 5.

### A2: Select from the lobby with the SELECT button

**Trigger:** A CONNECTED player presses SELECT
**Flow:**

1. System is meant to cycle the mode, but the handler calls a missing attribute and fails (likely bug D-M1).
2. Use case ends without a change.

### A3: Mode without voice or colour

**Trigger:** The new mode is Zombies or NonStop (step 3)
**Flow:**

1. System plays no announcement and shows the default orange (key mismatch, D-M8).
2. Use case continues at step 4.

## Postconditions

### Success Postconditions

- `current_game` holds the new mode; the next StartMenu restores it.

### Failure Postconditions

- The previous selection stays.

## Business Rules

### BR-001: Playable modes only

Commander, Ninja and Random are never offered.

### BR-002: The dashboard mode selector has no effect

The dashboard's start command ignores the selected mode (D-M9).
