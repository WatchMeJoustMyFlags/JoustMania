# Use Case: Play Joust Free-for-All

## Overview

**Use Case ID:** UC-020
**Use Case Name:** Play Joust Free-for-All
**Primary Actor:** Player
**Goal:** Be the last player standing
**Status:** Tested
**Requirements:** FR-020, FR-027, FR-030, FR-032, FR-035, FR-036

## Preconditions

- A JoustFFA game was started with at least two players (UC-010).

## Main Success Scenario

1. System assigns every player to team 0 with a white LED and publishes `players_initialized`.
2. System publishes `game_started`, plays the countdown (UC-010 step 6) and starts the game music at game volume.
3. Players try to jostle each other's controllers while keeping their own still.
4. System alternates the music between slow and fast windows (UC-031) and adjusts thresholds accordingly.
5. System eliminates any player whose movement exceeds the threshold (UC-030).
6. When one player is left, System publishes `game_winner` with the serial, shows a rainbow on the winner for `winner_rainbow_duration_ms` (default 3 s) and plays "congratulations".
7. System publishes `player_analytics` for each player and `game_ended` with the duration.

## Alternative Flows

### A1: Tie

**Trigger:** The last players die in the same frame (step 6)
**Flow:**

1. System publishes `game_tie` instead of `game_winner`.
2. Use case continues at step 7.

### A2: Player disconnects

**Trigger:** A controller disconnects during the game (step 3)
**Flow:**

1. System treats the disconnect as an elimination.
2. Use case continues at step 5.

### A3: Agent intervention

**Trigger:** The agent applies an intervention (UC-040)
**Flow:**

1. System applies it through the game's own code paths (e.g. tempo change, shield, elimination) and publishes `agent_intervention`.

## Postconditions

### Success Postconditions

- The game session is ENDED, the winner is in the event stream and the lobby is restored.

### Failure Postconditions

- On an internal error, System publishes `game_error` and ends the session.

## Business Rules

### BR-001: Win condition

The game ends when at most one player is alive; win detection runs after every frame and every disconnect.

### BR-002: Grace period

`death_grace_period_seconds` has no effect in FFA (no respawn).
