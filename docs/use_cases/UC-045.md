# Use Case: Stop the Agent with Flags

## Overview

**Use Case ID:** UC-045
**Use Case Name:** Stop the Agent with Flags
**Primary Actor:** Operator
**Goal:** Stop, or make inert, every in-game agent effect, the experiment loop and every paid model call immediately and reversibly (infrastructure rollout has its own gates, A4)
**Trigger:** Operator wants the agent to stop acting at once (for example a misbehaving backend, a cost concern, or a talk beat)
**Status:** Tested
**Requirements:** FR-042, FR-049, FR-050, FR-051, FR-066, NFR-050, NFR-052, C-002, C-030, C-032, C-034
**Planned:** FR-152 (#1788, Implemented; stays here until a UC-045-tagged test covers it)

## Preconditions

- The agent runs with the kill switch `enabled` on (the shipped baseline is off; an operator or the stage baseline turned it on).

## Main Success Scenario

1. Operator runs `scripts/agent-killswitch.sh off`: it removes the stack-wide `on` value of `enabled` from the flag service, so the fail-closed `off` baseline returns.
2. flagd serves `enabled` = off to the agent within the write-propagation bound (NFR-050), with no file edit and no agent restart.
   The agent sees the flip on its next read: it evaluates without a resolver cache ([flags.md §1.3](../specs/flags.md#13-reload-semantics)).
3. On its next decision cycle the agent stops evaluating and makes no decide call; instead it emits an `agent.disabled` span, at most one per `decision.throttle_seconds`.
4. Any remote answer still in flight is discarded on landing (`kill_switch`, [UC-040](UC-040.md) A6).
5. On the next experiment tick (`experiment_tick_seconds`, default 30 s) the agent aborts running experiments and force-ends any pattern game still in flight ([UC-046](UC-046.md) A12). On the same tick it removes every real-default overlay an autonomous promotion wrote (writer `promotion` on the flag service, also from before an agent restart; its `DELETE` carries `?if_writer=promotion`, so another writer's overlay is never removed, [UC-043](UC-043.md) A18, #1877), stops each promotion's re-watch and journals the revert (reason `kill_switch`, [UC-043](UC-043.md) A1, #1704). A promotion write in flight when the tick starts lands first and is reverted by that tick; a promotion that read its flags before the tick does not write after it. The tick repeats while `enabled` is off, so a failed revert is retried (journaled once, [UC-043](UC-043.md) A1, #1753).
6. From the next game end, the retro is capture-only and the experiment proposer does nothing ([UC-042](UC-042.md) A8, A5).
7. Later, operator runs `scripts/agent-killswitch.sh on` to resume: it sets `enabled` to `on` as a stack-wide value on the flag service, held in memory only, so a flag-service restart returns the agent to off ([UC-053](UC-053.md) A1).

## Alternative Flows

### A1: Observe without acting

**Trigger:** Operator turns `interventions_enabled` off instead (step 1)
**Flow:**

1. The agent keeps deciding and spanning, but writes no intervention; experiment-arm values and the rollout stage are not governed by this gate.
2. Use case ends.

### A2: Narrow the allow-list

**Trigger:** Operator sets `interventions_allowed` to `none` instead (step 1); [UC-013](UC-013.md) is the host's way to do the same from the controller
**Flow:**

1. The agent keeps running, but no intervention passes the agent or the coordinator, and on a remote backend the agent makes no decide call, so no model is called and no budget is charged (as UC-013 Post-S-1; [UC-040](UC-040.md) BR-005, A14).
2. Use case ends.

### A3: Flagd unreachable

**Trigger:** The agent cannot read flags (step 3): flagd is unreachable, or its in-process provider is not READY: no first flag sync yet, or the sync stream is lost (STALE / ERROR) until flagd sends again (#1713, [flags.md §1.1](../specs/flags.md#11-clients))
**Flow:**

1. `enabled`, `interventions_enabled`, `rollout_enabled` and `remediation_allowed` fail closed (off) and `interventions_allowed` resolves to an empty list; `experiments_enabled` and `experiment_dynamic_enabled` fail closed too (no env fallback, #1907), so the experiment loop and the proposer stop on either gate.
2. Use case ends.

### A4: Stop infrastructure remediation

**Trigger:** Operator wants the agent to stop expanding or rolling back the controller-backend rollout (step 1)
**Flow:**

1. `enabled` does not govern the infrastructure loop: with the agent off, it keeps observing `controller.bluetooth_health` and evaluating fitness.
2. Operator sets `rollout_enabled` off (agent flag set, read live per rollout action, [flags.md §1.3](../specs/flags.md#13-reload-semantics)); expansion and rollback become dry runs (decided, not applied), and the agent commits rollout state only for a write that landed (UC-050 BR-003).
3. Alternatively, operator sets `remediation_allowed` off; a failing stage is then only recommended (`remediation.action=recommended_only`), never rolled back automatically.
4. Operator turns the flag back on to resume (UC-050, UC-051); no agent restart is needed ([flags.md §1.3](../specs/flags.md#13-reload-semantics)). A rollback rehearsed during the dry run still holds the first real expansion until its cooldown ends (UC-050 BR-003).
5. Use case ends.

### A5: Flag service refuses or cannot be reached

**Trigger:** the flag service refuses to remove the value (for example `503 no_sync_stream` while flagd is not connected, [UC-053](UC-053.md) A7) or does not answer within the script's 5 s deadline (NFR-052) (step 1)
**Flow:**

1. The script prints that the flag service did not take the change and the fallback brake: stop the agent container (`docker stop joustmania-agent`); the game keeps running without the agent. It exits non-zero.
2. `enabled` stays on, and flagd keeps serving it, until the operator applies the brake or a retry succeeds.
3. Use case ends.

### A6: Resume refused

**Trigger:** the flag service refuses the `on` value or cannot be reached (step 7)
**Flow:**

1. The script prints the error and exits non-zero.
2. Use case ends; `enabled` stays off.

## Postconditions

### Success Postconditions

- While `enabled` is off, until step 7, no new agent effect reaches any game: from step 3 the agent makes no decide call and writes no intervention, from step 5 it runs no experiment, and no real-default overlay an autonomous promotion wrote survives: the kill-switch revert is its last real-default write (step 5), and from step 6 it makes no post-game model call. State interventions already written for a live game stay until that game ends (they are dropped with its scope, [UC-053](UC-053.md) BR-003).
- After step 7 the agent decides again from its next decision cycle.
- The infrastructure rollout is unaffected by `enabled`; it is stopped only through `rollout_enabled` / `remediation_allowed` (A4).
- Since #1788: the settings that limit the agent (autonomous promotion, code improvement, the remote-call ceiling) stay operator-owned and are never agent-writable; the remote-call cap is `min(AGENT_LLM_MAX_REQUESTS_PER_MINUTE, llm.max_requests_per_minute)`; this use case's flow is unchanged (FR-152).

### Failure Postconditions

- The agent can do no more than before the operator acted: a refused or failed change leaves `enabled` as it was (A5, A6).

## Business Rules

### BR-001: Three independent intervention gates

`enabled` (existence), `interventions_enabled` (actuation) and `interventions_allowed` (permission) are separate flags; any one can stop interventions. The experiment loop also needs `experiments_enabled`, and the infrastructure rollout has its own gates (`rollout_enabled`, `remediation_allowed`, A4).

### BR-002: Post-game model calls obey the kill switch

See [UC-042](UC-042.md) BR-002 and A5 (the proposer, including a flip during its model call) and UC-042 A8 (the retro): with `enabled` off neither makes a model call (FR-042, FR-066).
