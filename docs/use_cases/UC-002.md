# Use Case: Connect a Controller and Join the Lobby

## Overview

**Use Case ID:** UC-002
**Use Case Name:** Connect a Controller and Join the Lobby
**Primary Actor:** Player
**Goal:** Get a paired controller connected and shown as present in the lobby
**Status:** Implemented
**Requirements:** FR-002, FR-003, FR-004, FR-006, NFR-001, NFR-002

## Preconditions

- The controller was paired (UC-001).
- The controller manager runs with a backend set that includes a real adapter (`backend` flag, read at startup; default `python,rust`).
- The menu is running.

## Main Success Scenario

1. Player presses the PS button.
2. System's HID backend opens the device and streams sensor data (≈ 1 kHz).
3. System discovers the controller on its next discovery check (1 Hz) and routes it to one adapter (per-serial `bluetooth_backend` targeting, then the rollout, then the default).
4. System assigns the controller a stable name (generated from the serial on first sight, persisted).
5. System publishes a connect event on the button stream.
6. System's menu registers the controller as CONNECTED and lights its LED in the selected game mode's colour at 30 % brightness.

## Alternative Flows

### A1: Controller disconnects

**Trigger:** The serial disappears from the backend (any time)
**Flow:**

1. System removes it from the lobby and publishes a disconnect event.
2. System sets `controller_connected` to 0 for that serial.
3. Use case ends.

### A2: Operator renames the controller

**Trigger:** Operator calls RenameController from the dashboard (any time)
**Flow:**

1. System stores the new name in the names file.
2. Use case continues; the new name appears on spans and the dashboard.

### A3: Lobby idle

**Trigger:** No button press for `idle.timeout_minutes` (default 15)
**Flow:**

1. System switches connected controllers to IDLE (LED off) and animates up to `sentinel.count` sentinel controllers (UC-010 A2).

## Postconditions

### Success Postconditions

- The controller is tracked by the controller manager and shown CONNECTED in the lobby.

### Failure Postconditions

- The controller is not in the roster; no lobby state exists for it.

## Business Rules

### BR-001: One adapter per controller

Each controller is served by exactly one adapter per discovery cycle; routing changes apply on the next cycle without a reconnect.

### BR-002: Reserved mock controllers are hidden

Mock controllers reserved for shadow games never appear in the lobby roster.
