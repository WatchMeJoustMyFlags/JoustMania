# Use Case: Canary a Backend and Inject Chaos by Hand

## Overview

**Use Case ID:** UC-052
**Use Case Name:** Canary a Backend and Inject Chaos by Hand
**Primary Actor:** Operator
**Goal:** Move chosen controllers to another backend, or inject faults, with one HTTP call
**Status:** Implemented
**Requirements:** FR-006, FR-070, FR-073

## Preconditions

- The connect-proxy reaches the flag service (`FLAG_SERVICE_URL`).

## Main Success Scenario

1. Operator calls `POST /canary/rust?fraction=N` on the connect-proxy.
2. System changes `bluetooth_backend` through the flag service ([UC-053](UC-053.md) A1): at `fraction` 100 (the default) a stack overlay on the backend's variant; below 100 a stack overlay on the stable counterpart plus a fraction overlay, so `fraction` % of the controller serials resolve the backend and the rest the counterpart. `/canary/python` works the same way; `/canary/status` returns the flag service's view.
3. flagd receives the configuration at once; the controller manager routes the selected controllers to the rust adapter on its next cycle.
4. Operator queries `controller_routing_decisions_total` (VictoriaMetrics / Grafana Explore) and the "Controllers per Backend" panel of the Controllers & Bluetooth dashboard (uid `controller-overview`).
5. Operator calls `POST /canary/rollback` to return everyone to python.

## Alternative Flows

### A1: Inject chaos

**Trigger:** Operator calls `POST /chaos/{poll-drop|accel-spike|led-failure|disconnect}?fraction=N` instead of a canary (step 1)
**Flow:**

1. System changes `chaos_fault_type` through the flag service: a stack overlay, or a fraction overlay for `fraction` below 100.
2. The chaos adapter injects the fault for the targeted controllers; `controller_chaos_faults_injected_total` counts them. The chaos adapter wraps only real (non-mock) adapters, decided when the controller manager starts (a flag read that fails falls back to the default and still wraps them), so chaos has no effect on mock controllers.
3. `POST /chaos/reset` restores `none`; `/chaos/status` shows the current fault.
4. Use case ends.

### A2: Through envoy

**Trigger:** Operator calls `/canary/*` through the host entry point (port 80) (step 1)
**Flow:**

1. Envoy has no `/canary/` route; the request reaches the dashboard instead (D-B3). Call the connect-proxy from inside the network, or use `/chaos/`, which is routed.
2. Use case ends.

## Postconditions

### Success Postconditions

- The chosen controllers use the requested backend or fault.

### Failure Postconditions

- The flag service is unchanged (a refusal keeps its 4xx; the flag service unreachable is 502).

## Business Rules

### BR-001: Manual canary wins

Per-serial `bluetooth_backend` targeting takes precedence over the agent's rollout (UC-050).

**Code / tests:** `services/connect-proxy/canary.go`, `chaos.go`, `services/controller_manager/backend_factory.py` (`_maybe_wrap_chaos`), `services/controller_manager/multiplexer/multiplexer_backend.py` (`_resolve_adapter_for_serial`), `chaos_adapter.py`; `services/connect-proxy/flagservice.go`; tests `services/controller_manager/tests/`, `services/connect-proxy/canary_test.go` (handlers against a fake flag service).
