# Flag catalog (OpenFeature / flagd)

> Technical spec. Part of the [spec tree](../README.md). Also serves #1092 (agent-tunable flag catalog).
> State: `main` @ 81c9ecea (2026-10-16, includes PRs #1257, #1261, #1265; #1265 changed no flags). **Generated from the JSON files plus a call-site scan**, then
> hand-verified; every `file:line` was checked to exist. Regenerate rather than hand-edit when many rows change.

OpenFeature flags served by flagd are the **only** control surface of the system:
human settings, the agent's governor, the agent's own interventions and the infrastructure rollout
are all flags (northstar constraint C-002). This catalog lists every flag on `main`: **150 flags in 8
flag sets** (agent 63, game 31, interventions 17, controller 9, rollout 4, system 12, user 11, observability 3).

Rule (see [CONTRIBUTING](../CONTRIBUTING.md#spec-driven-development-aiup)): a new flag, a new variant, a
changed default or a new reader/writer updates this file in the same PR.

### 1.2 Evaluation context

- API level (Python): `service_name`, `service_namespace`, `language`, `environment`, `hostname`, `game_kind=real` (`lib/feature_flags.py:114-131`).
- Per game (transaction context): `targetingKey=game_mode`, `game_mode`, `controller_count`, `game_kind`, optional `sensitivity`, `experiment_id`, `arm` (`lib/feature_flags.py:488-546`). Calibration reads add `gameId` (`lib/feature_flags.py:242-253`).
- Interventions are evaluated per live session with `{targetingKey=serial, gameId}` (`services/game_coordinator/interventions.py:930-945`).
- `game_kind` vocabulary for flags is `real` / `shadow`; the protected value is `real` and targeting for experiments matches `game_kind != "real"`. Telemetry uses `primary` / `shadow`; see [entity_model.md](../entity_model.md#game_session).

### 1.3 Reload semantics

| Term | Meaning |
|---|---|
| **live** | Evaluated at use time (each call, cycle or tick). Takes effect after flagd reloads the file. |
| **event-refreshed** | Cached, re-read on OpenFeature `PROVIDER_CONFIGURATION_CHANGED`. Effectively live. |
| **per-game** | Read at game start (menu `StartGameConfig` or game `__init__`) and frozen for that game. |
| **startup** | Read once at process start. **Restart required.** |

Startup-only flags: controller `backend`, `effect.*` (5); observability `metrics_export_interval_ms`,
`otel_bsp_schedule_delay_millis`; user `menu_auto_start`, `audio_volume.lobby_music`,
`audio_volume.menu_sound`, `audio_volume.menu_voice`; and the wrap/no-wrap decision for `chaos_fault_type`.

Reload latency (file edit to new value) is **not measured**. Documented claims are "< 100 ms"
(`lib/flag_config_writer.py:24`) and "~1 s" (`scripts/agent-backend.sh`, agent runbooks). NFR-014 records
the ~1 s target as unverified.

**Traceability:** C-002, NFR-014 / UC-012, UC-044 / `docker-compose.yml`, `lib/feature_flags.py`, `lib/flag_config_writer.py`, `services/agent/flags/` / `lib/tests/`, `services/agent/flags/*_test.go`.

invariant 1 says the agent never persists into `game.json`; the experiment writer and the autonomous
promoter do (shadow-scoped and gated respectively), and the menu writer and the agent writer share
`game.json` without a lock.
