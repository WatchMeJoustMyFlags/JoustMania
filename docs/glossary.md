# Glossary

> Part of the [spec tree](README.md), next to [requirements](requirements.md) and the
> [entity model](entity_model.md). State: `main` @ a74d0d77 (2026-10-20). One meaning per term: when a
> word has several meanings in the code (gate, stage, backend), each meaning is its own row and the
> spec names the qualified term. Items from open PRs are marked with the PR number.

| Term | Definition | Avoid / synonyms |
|---|---|---|
| **Act** (outcome) | `decide.outcome=act` on the `agent.decide` span: the answer is routed to the permission chain, which may still block it (see the child `agent.decision`). It is also the rules path's default outcome. It does not mean the intervention was applied ([decide contract §6](specs/decide-contract.md#6-outcomes)). | "applied", "executed" (applying is the coordinator's job, after the actuation gate) |
| **Actuation gate** | The `interventions_enabled` flag: with it off, the agent decides and records spans but writes no intervention (FR-051); experiment-arm and rollout writes have their own gates (UC-045 A1, A4). | "kill switch" (that is `enabled`) |
| **Admin mode** | The controller button interface of the menu: a PS Move enters it with a button combo, and the host changes settings with buttons; feedback is an LED colour pulse and a voice line (UC-012, UC-013). The system is headless: there is no screen, and the dashboard (UC-035) is a read-only observer. | "admin menu", "admin UI", "admin display" |
| **Archetype** | A named parameter object (an object variant of the `agent.json` flag `experiment.mock_archetype`, e.g. `slow_cascade`) that defines the motion function of every player of a pattern game: game parameters plus per-slot modifiers (UC-046 BR-003); identified by its name and parameter digest (C-019). (#1258) | "parameter set" (the earlier file-based design), "profile" (a `pacing_profile` is an intervention) |
| **Backend** (decision) | What answers the decide questions in game: `rules`, `claude`, `openai`, `jev`, selected live by `decision.backend` (FR-045, C-018). | Unqualified "backend" when another kind is meant: the **controller I/O backend** (`python`, `rust`, `mock`, `unstable`; flag `backend`, FR-006), the **rollout target backend** (`target_backend`, FR-071) and the **inference backend** of the retro / proposer (flag `inference.backend`) are different things. |
| **Backup backend** | Claude in game, selected only by a manual `decision.backend` flip (C-018). | "fallback" (the automatic floor is rules) |
| **Beat** | One scripted step of the talk demo, one command each (UC-070 main steps 1 to 9; A1, A6 and A7 are optional beats). | "scene", "act" (an `act` is a decide outcome) |
| **Cadence gate** | `decision.min_interval_ms`: at most one remote decide call per game per interval (from when the previous call started); `decision.min_gap_after_answer_ms`: no call before the previous call ended (answer, timeout or failure) plus the gap (#2123); never two in flight (NFR-012). Gated calls count as `agent_llm_gated_total{reason=decide_interval}`. | "rate limit" (that is the intervention budget, NFR-015) |
| **Confidence** | The backend's confidence in [0,1] that acting on the answer is right; routing compares the `ffa.intervention` confidence with the act threshold. Per backend: **rules** = 1 − p(noop) when an intervention is chosen, p(noop) when `noop` is chosen; **claude** / **openai** = self-reported by the model; **jev** = the gate's p_yes for an intervention choice and 1 − p_yes for `noop` (#1286); Jev's native confidence applies only to the other questions and is recorded as `jev.native_confidence`; for a **noul** answer Jev uses \|2p − 1\|, while rules answer a noul at confidence 0 ([decide contract §5](specs/decide-contract.md#5-confidence-and-routing)). | "probability" (a probability is per option; confidence is per answer) |
| **Connection quality** | A controller's link rating `good` / `fair` / `poor` from its p95 and longest gap between fresh frames over a rolling 10 s window; the worse of the two ratings (UC-035 BR-005, FR-122). Unknown until two fresh frames arrived. | "signal strength" (RSSI is a separate Bluetooth reading) |
| **Convention play mode** | The stage Pi at a venue without internet: the stack runs offline (UC-060 BR-001), the agent decides with the rules backend (remote backends fail over to rules), and the Host reaches it over the stage hotspot (UC-061). | "offline mode" (not a switch: it is what the system does without a network) |
| **Cross-game window** | The agent's in-memory history of recent finished games, game-level aggregates only, no controller identity; real games in one ring, shadow games in the linked set of their experiment (UC-042 BR-004, BR-005, C-009). Lost on restart. | "game history" (nothing is persisted) |
| **Degrade** | The game keeps playing without a remote model: when the selected decision backend is slow, unreachable, over budget, ineligible or invalid, rules decide (C-004, FR-048). | "degradation" in the fitness sense: a **fitness degradation** (UC-051 rollback, FR-065 revert) is a measured drop in infrastructure or game fitness, not a backend failure |
| **Discarded** (outcome) | `decide.outcome=discarded`: a remote answer dropped when it landed, or a call cancelled, because the situation changed; under the kill switch a failed or timed-out call is also `discarded` (UC-040 A6) (`decide.discarded_reason`: `stale_context`, `game_ended`, `target_gone`, `target_stale`, `state_too_old`, `kill_switch`, `backend_changed`, `shutdown`; FR-049). | "cancelled" for a call that still landed; a timeout without the kill switch is a `fallback` |
| **End reason** (agent) | Which signal ended a game in the agent's view: `zero` (`game_active` 1 to 0), `root_span` (the game root span arrived first) or `stale` (`game_active` silent for 60 s, so the game's data is incomplete and experiments, retro, summary and proposer skip it) (UC-041 A4, #1494). Not the coordinator's force-end `reason` (`game.end_reason`). | "outcome" (winner, tie, timeout) |
| **Evaluation gate** | Whether the agent evaluates a game's context at all: the game is active and at least one player is a fresh player (`services/agent/gate`, UC-040 Trigger). A context that fails it is not evaluated and nothing is recorded. | Unqualified "gate" (see **Gate**) |
| **Exact replay** | A pattern game that qualifies for replay comparison: `decision.backend` was `rules` at every decision, 0 stream frame overruns, no other game live at its start, end or once-per-second checks, the kill switch did not end it, its chaos rolls were all seeded, and its flag digest was available (UC-046 BR-008, BR-011). Otherwise it is non-exact with reasons `remote_backend`, `frame_overrun`, `concurrent_game`, `kill_switch`, `unseeded_draws`, `flag_digest_unavailable`. A `timeout` outcome alone does not make a game non-exact. (#1258) | "deterministic game" (the input signal is always exact; only the outcome needs these conditions) |
| **Experiment** | A hypothesis about one `game.json` flag value with an objective and a target sample size, tested in paired shadow games (experimental and control arms sharing a seed) until a cohort verdict (FR-060 to FR-063, UC-043). | "A/B test on players" (real players never see a variant before promotion) |
| **Fallback** (outcome) | `decide.outcome=fallback`: the requested backend could not decide and rules did, or, with `discarded_reason`, nothing was decided because the context is gone (UC-040 A2); `fallback_reason` says why ([decide contract §7](specs/decide-contract.md#7-fallback-reasons), FR-048). | "backup" (the backup backend is chosen by hand) |
| **Flag baseline** | The flag values the flag service loads from `services/flagd/<set>.json` (or `ci/<set>.json`) at start; it never writes them back. Persisted admin settings from the service's own state file are applied over it (C-030). Delivered by #1417 (epic #1407). | "stage baseline" (that is the talk's start state, a set of overlays), "consumed baseline" (the coordinator's per-game nonce baseline of UC-040, which the flag service makes unnecessary) |
| **Force-end** | An operator or agent ends a running game early (UC-027). It declares no winner: `game_ended` carries outcome `force_ended` and a `reason`, and a win already latched is kept (UC-020 BR-003). Not the agent's **End reason** (how the agent saw a game end). | "abort", "cancel" (a cancelled start publishes no `game_ended`, UC-010 A7) |
| **Flag service** | The in-memory service (`services/flag-service/`, delivered by #1417, epic #1407) that holds runtime flag state, merges every flag set into one flagd configuration (flags tagged with their `metadata.flagSetId`) and serves it to stock flagd over one `flagd.sync.v1` gRPC sync source; writers call `PUT /{flagSetId}/{flagName}` (UC-053, epic #1407). | "flag management service", "flag server" (it evaluates nothing; flagd does) |
| **Forfeit** | A Fight Club player who disconnects while fighting loses that round and the opponent scores (UC-025 A4 step 4). In Tournament the opponent of a player who is out advances by **walkover**, without playing the match (UC-025 A4 step 2). | "disqualification" |
| **Fresh player** | An active player whose last signal reached the agent within `lifecycle.player_ttl_seconds` (default 5 s). This row is the owner of the definition; UC-040 Trigger cites it. | "live player", "connected player" (a controller can be connected and still silent) |
| **Game event list** | The value of a one-shot intervention flag in one game, held by the flag service: `{"epoch","seq","events"}` with the last 16 events, each with its sequence number and payload (the serial for a player-targeted event). A game starts with an empty list, so every event fires once in its game only (UC-053 BR-006). Delivered by #1417; replaced the nonce of the former edge flags. | "nonce" (the removed design) |
| **Game scope** | The flag service's record of one live game (id, kind, serials, experiment, arm), registered by the game coordinator at admission and dropped at the game's end, with every value written for that game (FR-135). In-memory; delivered by #1417. | "session bucket" (the coordinator's per-game nonce state) |
| **Game stream** / **Observer stream** | A gameplay stream that sent player colours (it claims its controllers and receives their disconnects and health) versus one that never did, such as the dashboard's `WatchGameplayData` (UC-035 BR-006, UC-002 BR-004). | "dashboard game stream" for the observer |
| **Game time** (t) | The clock of a pattern game's motion functions: t = k / r, with k the index of the frame delivered for that controller (0 for the first) and r the archetype's pinned stream rate (UC-046 BR-001). Independent of host load and wall time. (#1258) | "elapsed time", "wall time" (game timers such as grace and tempo windows still use the wall clock) |
| **Gate** (Jev gate) | Jev's stage-1 yes/no question "should the agent act now?", answered as p_yes. Jev picks its stage-1 intervention only when p_yes > 0.5; it acts only if p_yes also reaches the act threshold (`decision.jev.act_confidence_threshold`, default 0.6, #1288). | Unqualified "gate". The other gates are separate terms: **threshold variant `gate`** (the 0.6 variant of `decision.act_confidence_threshold` and `decision.jev.act_confidence_threshold`, #1286 / #1288), the **actuation gate**, the **evaluation gate**, the **permission gate**, the **cadence gate**, the **LLM gate**, the **invariant gate** and the **promotion gates**. |
| **Held** (outcome) | `decide.outcome=held`: a valid remote intervention answer whose confidence is below the act threshold. Nothing happens and nothing is queued (FR-047). | "shadowed", "queued" |
| **Game outcome** | How a game ended: `winner`, `tie`, `force_ended`, or `completed` (UC-020 BR-003, `game_ended.outcome`). `games_completed_total{outcome}` uses the same values plus `error` (five label values, UC-020 BR-003). A failed run publishes `game_error` and no `game_ended`, so `error` is never a `game_ended.outcome` value; it also appears on the game root span. Distinct from the decide **outcome** (Act, Held, Noop, Fallback, Discarded) and the pattern game's `pattern_outcome` (UC-046). | "result" |
| **Hotspot** (stage) | The password-protected 5 GHz Wi-Fi access point the stage Pi opens on `wlan0` as a fallback when its uplink has no connection (UC-061, FR-184); address `10.42.0.1`, no internet. | "Wi-Fi", "access point" alone; "phone hotspot" (the Pi joining a phone as a client is UC-061 A2) |
| **Intervention** | A tier-1, bounded, reversible change to one running game (tempo, sensitivity, difficulty, shields, eliminate, revive, end game, cues, volume) written by the agent to the flag service for the game whose loop decided it and applied by the game coordinator (FR-053, FR-136). Limited by the allow-list, the actuation gate and the intervention budget. | "action" (an action is any agent write, including rollout and experiment writes), "decision" (a decision may be `noop`) |
| **Invariant gate** | `services/agent/experiment/gate.go`: rejects an experiment write that would change what a real game resolves, or that targets `agent.json` (FR-062). | |
| **Kill gate** | A game mode's check, before any death bookkeeping, of whether a kill is taken (`_accepts_kill`); a declined kill changes nothing and records no `player_death` (UC-030 step 9, #1383). The default gate declines once the outcome is latched. A game-mode rule, not one of the agent gates (see **Gate**). | "permission gate" (that is `interventions_allowed`) |
| **Kill switch** | The `enabled` flag in `agent.json`: off stops in-game decisions within one cycle, aborts experiments (an aborted experiment is not resumed when `enabled` turns on again, UC-043 A1) and stops every post-game model call (retro, proposer) from the next game end (FR-042, FR-066, UC-045). It does not stop the infrastructure rollout; that is `rollout_enabled` / `remediation_allowed` (UC-045 A4). The host's "kill switch on the controller" sets `interventions_allowed` (the permission gate, FR-019). | "off switch for everything" |
| **Linked set** | The cross-game window's shadow history of one experiment, keyed by `experiment_id`: at most 20 games, visible only to games of that experiment, evicted when the experiment is torn down (UC-042 BR-005). | "shadow window" |
| **LLM gate** | `llm.eligible_game_kinds` plus the shared `llm.max_requests_per_minute` budget, checked by in-game decisions, the retro and the proposer before a model call (NFR-011). | |
| **Main in-game backend** | Jev, the decision backend intended for in-game decisions (C-018). The shipped default of `decision.backend` is still `rules`. | "primary backend" (`primary` is a telemetry game kind) |
| **Motion pattern** | The deterministic motion function intensity_i(t) = base_i + drift_i·t + amp_i·sin(2π(t/period_s + phase_i)) + burst_i(t) of one player of a pattern game, clamped to 0..10 g (UC-046 BR-002). (#1258) | "scenario" (a demo-driver script, FR-092), "noise" (today's random mock motion) |
| **Mutable-flag registry** | The list of flags that may change at runtime, with the kind, scope, bounds and persistence of each ([flags.md §13](specs/flags.md#13-mutable-flag-registry), FR-132); every other flag is read-only baseline. There are no writer roles. Delivered by #1417. | "flag catalog" (the agent-tunable catalog of #1092 is an input, not the registry) |
| **Noop** (outcome) | `decide.outcome=noop`: the backend chose the `noop` intervention. No action. | "held" (held is a below-threshold intervention) |
| **Overlay** | A runtime value the flag service holds on top of the flag baseline: stack-wide (rendered as a `defaultVariant` substitution, so baseline targeting still wins), for one game, for one player in a game, for an experiment arm or for a fraction of controllers. In memory, except admin settings (those are also kept in the service's state file). Delivered by #1417. | "override" when the `*_override` intervention flags are not meant |
| **Pattern game** | A shadow game whose mock controllers are driven by an archetype, with organic deaths only; every shadow experiment game and every one-shot shadow game is a pattern game (random resting motion is left only to mock controllers outside experiments); its length emerges from the parameters, thresholds, tempo and interventions, bounded by the safety cap `experiment.max_game_seconds` (UC-046). (#1258) | "scripted game" (nothing kills a player on a schedule) |
| **Perceptible intervention** | An intervention a player or the audience notices on the stack in use, mock controllers included: `play_audio_cue` (when its sound resolves), `grant_shield`, `toughness_boost`, `adjust_music_tempo`, `ramp_tempo`, `eliminate_player`, `revive_player`, `end_game`. `send_controller_effect` (default `rumble`) and `adjust_volume` are not: mock controllers cannot rumble and 0.7 volume is barely audible (#1301, UC-070 BR-004). | "visible" when audible is meant |
| **Permission gate** | The allow-list `interventions_allowed` (the host ladder `none`, `ambient`, `standard`, `full`, plus the operator variants `probe` and `shadow_experimental`), enforced by the agent and again by the coordinator (FR-050). | |
| **Planned** (use-case field) | The `**Planned:**` line in a use case's overview: FRs that only a planned flow needs, each with its issue number and status `Open`. They count as referenced (traceability) but do not cap the use case's status, which follows the FRs on its `Requirements:` line ([CONTRIBUTING](CONTRIBUTING.md#status-vocabularies)). | Listing an `Open` FR under `Requirements:` of an `Implemented` use case |
| **Primary** (game kind, telemetry) | The game coordinator's telemetry label (`game_kind` metric label, `game.kind` span attribute) for the menu-started, player-facing game. The agent normalises it to `real` at ingest (#1249, FR-041). | Using "primary" for a decision backend |
| **Promotion gates** | What must hold before a promote verdict changes anything: `code_improvement.mode` and the other `code_improvement.*` flags, `enabled`, and the env gates `AGENT_CODE_IMPROVEMENT_ENABLED`, `AGENT_AUTONOMOUS_ENABLED`, `GITHUB_*` (D-A6; the stock stack passes none, so promotions are only recorded) (FR-064, FR-065). | |
| **Real** (game kind, flags) | The flag-evaluation and agent vocabulary for a player-facing game. Only an explicit `real` (or telemetry `primary`) counts as real; an empty or unknown kind never does (fail closed, FR-041). | "primary" outside telemetry; treating an unlabeled game as real |
| **Retro** (post-game summary) | The agent's post-game review of one eligible ended game: at most one model call that returns a session assessment, suggestions and a focus, recorded with `inference_used=none` and a `fallback_reason` when no call is made, except when the shared budget is exhausted, which records no span and no row (UC-042 A2) (RETRO, UC-042); "summary" and "session assessment" in UC-070 step 8 are this. | "game summary" (that is GAME_SUMMARY, the agent's own record of a game) |
| **Service epoch** | The boot id of the flag service: it is part of every generated variant name and of every game event list, so a value from before a restart is never mistaken for a new one (`GET /state`). Delivered by #1417. | |
| **Shadow** | A headless game with mock controllers started by the agent (`game_kind=shadow`, its own game id and event stream), used for experiments and never affecting real players (FR-029); also **shadow-scoped targeting**, a `game.json` variant that only non-real games resolve (FR-062). | "shadow" as a decide outcome (proposed in epic #1225, never shipped; the outcome is `held`) |
| **Signal hash** | FNV-1a/64 over a controller's delivered frames in milli-g, recorded when a pattern controller is removed, together with **checkpoint hashes** (the hash after every second of game time); replays compare the checkpoints on their common prefix ([telemetry.md §9](specs/telemetry.md#9-pattern-games-1258)). Called "signal fingerprint" in use-case steps. (#1258) | |
| **Slot** (controller slot) | Index i = 0..N−1 of a controller in a pattern game's reservation order, which selects its motion pattern; never the serial, because mock serials are not reused (UC-046 BR-006). (#1258) | "player number", "serial" |
| **Stage** (budget variant) | The `stage` variant of `llm.max_requests_per_minute` (30 calls per minute) for the talk (PR #1257). | Unqualified "stage". **`jev.stage`** is a chat-span attribute (`intervention`, `details`, `single`) naming one HTTP call of Jev's two-stage round; a **rollout stage** is a step of `current_controller_count` (0, 1, 3, 6, all) in the progressive rollout (FR-071). |
| **Stage baseline** | The flag state the talk starts every beat from; UC-070 BR-003 owns the value list. It lives in `scripts/talk-baseline.json`, applied by `scripts/talk-stage.sh reset` and checked by `scripts/talk-preflight.sh`; the shipped flag files keep their own defaults (`interventions_allowed=ambient`). | "default" (the shipped `defaultVariant` is a different thing) |
| **Shield feedback** | What a player notices when the agent shields them: the `shield_up` sound and the `GAME_EFFECT_SHIELD` LED (white, fades over the shield, blinks in the last second, then the player colour returns); `toughness_boost` gets the weaker `GAME_EFFECT_TOUGHNESS_BOOST` (UC-040 A16, BR-008 to BR-010). It mirrors the protection and never changes it. | "shield" for the LED alone (the shield is the protection, `grace_until`) |
| **Shield energy** | In a hold game (`shield.activation` = `hold`, #2096), a player's pool of shield seconds: agent grants and the optional recharge fill it up to the cap, holding the trigger spends it (UC-040 BR-024, UC-030 A7). | "charge" (a charge is the one-shot of trigger mode) |
| **Shield budget** | The active shield time one player may use in one hold game, summed over every activation (`shield.energy_budget_seconds`, default 15 s); once used up, the shield cannot activate again in that game (UC-040 BR-024). | "cap" (the cap is the most energy held at once) |
| **Minimum burst** | The least one hold activation costs (`shield.min_burst_seconds`, default 0.3 s); a press again inside it continues the same activation (UC-030 BR-008). | "debounce" alone |
| **Tier** | The northstar's risk tiers: 1 in-game interventions (apply directly), 2 persistent tuning (only after shadow validation), 3 changes needing a compile step (proposals reviewed by a human) ([NORTHSTAR](NORTHSTAR.md)). | |
| **Toughness boost** | The weaker agent grant (`toughness_boost`, flag `toughness_boost_seconds`, `GAME_EFFECT_TOUGHNESS_BOOST`): it raises one player's death and warning thresholds by a factor of 1.0 to 2.0 for 3 to 10 s (30 s at most), shadow-only. Renamed from the retired id `partial_shield` (#1838) | "partial shield" (the retired name; the word "shield" is kept for the full `grant_shield` protection) |
| **Voice catalog** | The text source of every voice line, `services/audio/voice/lines.yaml`: per area the file stem, the `Sound` member, the text and an optional respelling; `make voice` renders it for each generated **voice profile** (UC-031 BR-007, #2107). | "voice list" |
| **Voice profile** | One directory name under `<area>/vox/`: the generated `gen_female` (the default) and `gen_male`, one Piper voice each and each the other's partner (UC-031 BR-007). | "voice" for a generated profile alone |
| **Win latch** | The step that freezes a game's result (winner, tie or no winner, and the game outcome) once, in the step that decides the win and before the `*_winner` event is published, so a later force-end keeps the win and its end-of-game effects (UC-020 BR-003; per mode in UC-021..026). After it the default **kill gate** declines every kill. | "lock" |
