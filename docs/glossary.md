# Glossary

> Part of the [spec tree](README.md), next to [requirements](requirements.md) and the
> [entity model](entity_model.md). State: `main` @ 7d25ade4 (2026-10-16). One meaning per term: when a
> word has several meanings in the code (gate, stage, backend), each meaning is its own row and the
> spec names the qualified term. Items from open PRs are marked with the PR number.

| Term | Definition | Avoid / synonyms |
|---|---|---|
| **Act** (outcome) | `decide.outcome=act` on the `agent.decide` span: the answer is routed to the permission chain, which may still block it (see the child `agent.decision`). It is also the rules path's default outcome. It does not mean the intervention was applied ([decide contract §6](specs/decide-contract.md#6-outcomes)). | "applied", "executed" (applying is the coordinator's job, after the actuation gate) |
| **Actuation gate** | The `interventions_enabled` flag: with it off, the agent decides and records spans but writes nothing to `interventions.json` (FR-051). | "kill switch" (that is `enabled`) |
| **Backend** (decision) | What answers the decide questions in game: `rules`, `claude`, `openai`, `jev`, selected live by `decision.backend` (FR-045, C-018). | Unqualified "backend" when another kind is meant: the **controller I/O backend** (`python`, `rust`, `mock`, `unstable`; flag `backend`, FR-006), the **rollout target backend** (`target_backend`, FR-071) and the **inference backend** of the retro / proposer (`AGENT_INFERENCE_BACKEND`) are different things. |
| **Backup backend** | Claude in game, selected only by a manual `decision.backend` flip (C-018). | "fallback" (the automatic floor is rules) |
| **Cadence gate** | `decision.min_interval_ms`: at most one remote decide call per game per interval, never two in flight (NFR-012). Gated calls count as `agent_llm_gated_total{reason=decide_interval}`. | "rate limit" (that is the intervention budget, NFR-015) |
| **Confidence** | The backend's confidence in [0,1] that acting on the answer is right; routing compares the `ffa.intervention` confidence with the act threshold. Per backend: **rules** = 1 − p(noop) when an intervention is chosen, p(noop) when `noop` is chosen; **claude** / **openai** = self-reported by the model; **jev** = Jev's native confidence of the chosen option on `main`, and the gate's p_yes (1 − p_yes for `noop`) after PR #1286; a **noul** answer = \|2p − 1\| ([decide contract §5](specs/decide-contract.md#5-confidence-and-routing)). | "probability" (a probability is per option; confidence is per answer) |
| **Degrade** | The game keeps playing without a remote model: when the selected decision backend is slow, unreachable, over budget, ineligible or invalid, rules decide (C-004, FR-048). | "degradation" in the fitness sense: a **fitness degradation** (UC-051 rollback, FR-065 revert) is a measured drop in infrastructure or game fitness, not a backend failure |
| **Discarded** (outcome) | `decide.outcome=discarded`: a valid remote answer dropped when it landed because the situation changed (`decide.discarded_reason`: `stale_context`, `game_ended`, `target_gone`, `kill_switch`, `backend_changed`, `shutdown`; FR-049). | "cancelled", "timed out" (a timeout is a `fallback`) |
| **Experiment** | A hypothesis about one `game.json` flag value with an objective and a target sample size, tested in paired shadow games (experimental and control arms sharing a seed) until a cohort verdict (FR-060 to FR-063, UC-043). | "A/B test on players" (real players never see a variant before promotion) |
| **Fallback** (outcome) | `decide.outcome=fallback`: the requested backend could not decide and rules did; `fallback_reason` says why ([decide contract §7](specs/decide-contract.md#7-fallback-reasons), FR-048). | "backup" (the backup backend is chosen by hand) |
| **Gate** (Jev gate) | Jev's stage-1 yes/no question "should the agent act now?", answered as p_yes; Jev acts with its stage-1 pick only when p_yes > 0.5 (PR #1286, open). | Unqualified "gate". The other gates are separate terms: **threshold variant `gate`** (the 0.6 variant of `decision.act_confidence_threshold` / `decision.jev.act_confidence_threshold`, PRs #1286 / #1288), the **actuation gate**, the **permission gate**, the **cadence gate**, the **LLM gate**, the **invariant gate** and the **promotion gates**. |
| **Held** (outcome) | `decide.outcome=held`: a valid remote intervention answer whose confidence is below the act threshold. Nothing happens and nothing is queued (FR-047). | "shadowed", "queued" |
| **Intervention** | A tier-1, bounded, reversible change to one running game (tempo, sensitivity, difficulty, shields, eliminate, revive, end game, cues, volume) written by the agent to `interventions.json` and applied by the game coordinator (FR-053). Limited by the allow-list, the actuation gate and the intervention budget. | "action" (an action is any agent write, including rollout and experiment writes), "decision" (a decision may be `noop`) |
| **Invariant gate** | `services/agent/experiment/gate.go`: rejects an experiment write that would change what a real game resolves, or that targets `agent.json` (FR-062). | |
| **Kill switch** | The `enabled` flag in `agent.json`: off stops in-game decisions within one cycle, aborts experiments and stops every post-game model call (retro, proposer) from the next game end (FR-042, FR-066, UC-045). It does not stop the infrastructure rollout; that is `rollout_enabled` / `remediation_allowed` (UC-045 A4). The host's "kill switch on the controller" sets `interventions_allowed` (the permission gate, FR-019). | "off switch for everything" |
| **LLM gate** | `llm.eligible_game_kinds` plus the shared `llm.max_requests_per_minute` budget, checked by in-game decisions, the retro and the proposer before a model call (NFR-011). | |
| **Main in-game backend** | Jev, the decision backend intended for in-game decisions (C-018). The shipped default of `decision.backend` is still `rules`. | "primary backend" (`primary` is a telemetry game kind) |
| **Noop** (outcome) | `decide.outcome=noop`: the backend chose the `noop` intervention. No action. | "held" (held is a below-threshold intervention) |
| **Permission gate** | The allow-list `interventions_allowed` (`none`, `ambient`, `standard`, `full`), enforced by the agent and again by the coordinator (FR-050). | |
| **Primary** (game kind, telemetry) | The game coordinator's telemetry label (`game_kind` metric label, `game.kind` span attribute) for the menu-started, player-facing game. The agent normalises it to `real` at ingest (#1249, FR-041). | Using "primary" for a decision backend |
| **Promotion gates** | What must hold before a promote verdict changes anything: `code_improvement.mode` and the other `code_improvement.*` flags, `enabled`, and the env gates `AGENT_CODE_IMPROVEMENT_ENABLED`, `AGENT_AUTONOMOUS_ENABLED`, `GITHUB_*` (D-A6; the stock stack passes none, so promotions are only recorded) (FR-064, FR-065). | |
| **Real** (game kind, flags) | The flag-evaluation and agent vocabulary for a player-facing game. Only an explicit `real` (or telemetry `primary`) counts as real; an empty or unknown kind never does (fail closed, FR-041). | "primary" outside telemetry; treating an unlabeled game as real |
| **Shadow** | A headless game with mock controllers started by the agent (`game_kind=shadow`, its own game id and event stream), used for experiments and never affecting real players (FR-029); also **shadow-scoped targeting**, a `game.json` variant that only non-real games resolve (FR-062). | "shadow" as a decide outcome (proposed in epic #1225, never shipped; the outcome is `held`) |
| **Stage** (budget variant) | The `stage` variant of `llm.max_requests_per_minute` (30 calls per minute) for the talk (PR #1257). | Unqualified "stage". **`jev.stage`** is a chat-span attribute (`intervention`, `details`, `single`) naming one HTTP call of Jev's two-stage round; a **rollout stage** is a step of `current_controller_count` (0, 1, 3, 6, all) in the progressive rollout (FR-071). |
| **Tier** | The northstar's risk tiers: 1 in-game interventions (apply directly), 2 persistent tuning (only after shadow validation), 3 changes needing a compile step (proposals reviewed by a human) ([NORTHSTAR](NORTHSTAR.md)). | |
